# Graph

یک وب‌اپ برای برگزاری جلسه‌های صوتی، تصویری و چت گروهی روی شبکه محلی، بدون نیاز به اینترنت جهانی.

## ویژگی‌ها

- بک‌اند با `Node.js` و بدون وابستگی خارجی
- فرانت‌اند با `HTML`، `CSS` و `JavaScript`
- ذخیره کاربران، اتاق‌ها و پیام‌ها در فایل‌های `JSON`
- ارتباط تصویری/صوتی با `WebRTC` در شبکه داخلی
- چت گروهی و مدیریت شرکت‌کنندگان
- طراحی مینیمال و ریسپانسیو
- اعتبارسنجی نشست برای جلوگیری از جعل درخواست
- هدرهای امنیتی و کاهش ریسک XSS در رابط کاربری
- ورود به جلسه با نام کاربری دلخواه و رمز جلسه
- لینک دعوت برای اشتراک‌گذاری سریع داخل شبکه محلی
- رمزنگاری سرتاسری برای چت و سیگنال‌های WebRTC با رمز جلسه
- تلاش برای رمزنگاری سرتاسری صوت و تصویر در مرورگرهای پشتیبانی‌شده با salt چرخشی 5 دقیقه‌ای

## اجرا

```bash
cd /home/arko2ek/local-meeting-app
npm start
```

سپس در مرورگر دستگاه‌های داخل همان شبکه داخلی باز کنید:

```text
http://IP-SERVER:3000
```

مثال:

```text
http://192.168.1.20:3000
```

## جریان کار

1. سازنده جلسه نام خود، عنوان جلسه و رمز جلسه را وارد می‌کند.
2. سیستم یک کد اتاق می‌سازد و جلسه را ایجاد می‌کند.
3. داخل جلسه، لینک دعوت در اختیار سازنده قرار می‌گیرد.
4. افراد دیگر با باز کردن لینک، فقط نام کاربری دلخواه و رمز جلسه را وارد می‌کنند.
5. در صورت درست بودن رمز، وارد جلسه می‌شوند.

## علت کار نکردن دوربین و میکروفون

- بیشتر مرورگرها روی آدرس‌های `http://192.168.x.x` یا `http://10.x.x.x`، دسترسی به `camera`، `microphone` و `screen sharing` را مسدود می‌کنند.
- استثنای معمول فقط `http://localhost` است؛ اما این فقط روی همان دستگاه سرور جواب می‌دهد، نه بقیه کلاینت‌های LAN.
- برای اینکه همه کلاینت‌های شبکه داخلی بتوانند از رسانه زنده استفاده کنند، برنامه را با `HTTPS` محلی اجرا کنید.

## فعال‌کردن HTTPS محلی

سرور اگر فایل‌های زیر را پیدا کند، نسخه امن را هم بالا می‌آورد:

- `certs/server.key`
- `certs/server.crt`

پس از قرار دادن این فایل‌ها، برنامه علاوه بر HTTP روی این آدرس هم اجرا می‌شود:

```text
https://IP-SERVER:3443
```

### ساخت گواهی محلی با OpenSSL

نمونه:

```bash
mkdir -p certs
openssl req -x509 -newkey rsa:2048 -nodes \
  -keyout certs/server.key \
  -out certs/server.crt \
  -days 365 \
  -subj "/CN=192.168.1.20"
```

بعد از آن، در مرورگر هر کلاینت:

- آدرس `https://IP-SERVER:3443` را باز کنید
- هشدار گواهی را یک‌بار تأیید کنید
- مجوز `Camera` و `Microphone` را روی `Allow` بگذارید

## نکات رسانه

- `اشتراک صفحه` معمولاً فقط با کلیک مستقیم کاربر فعال می‌شود
- اگر دوربین یا میکروفون توسط برنامه دیگری گرفته شده باشد، مرورگر خطای دسترسی می‌دهد
- بعضی مرورگرهای قدیمی یا WebViewها `getDisplayMedia` را ندارند

## ساختار پروژه

- `server.js`: سرور HTTP، APIها و مدیریت فایل‌های JSON
- `public/index.html`: صفحه ساخت و ورود به اتاق
- `public/room.html`: صفحه جلسه
- `public/styles.css`: استایل مینیمال
- `public/app.js`: منطق صفحه اصلی
- `public/room.js`: منطق جلسه، WebRTC، چت و مدیریت کاربران
- `certs/`: گواهی محلی برای HTTPS داخل شبکه
- `data/*.json`: ذخیره‌سازی فعلی

## نکات مهم

- این نسخه برای LAN / Intranet طراحی شده است.
- رسانه WebRTC به‌صورت پیش‌فرض در مسیر انتقال رمزگذاری می‌شود.
- در این نسخه، چت و سیگنال‌دهی با رمز جلسه و salt زمانی 5 دقیقه‌ای به شکل E2E محافظت می‌شوند.
- برای صوت و تصویر نیز در مرورگرهای پشتیبانی‌شده از encoded transforms، رمزنگاری سرتاسری مرورگر-محور فعال می‌شود؛ در مرورگرهای فاقد پشتیبانی، فقط رمزنگاری استاندارد WebRTC برقرار است.
- لینک دعوت فقط کد اتاق را حمل می‌کند؛ رمز جلسه باید به صورت جداگانه و امن به شرکت‌کنندگان داده شود.
- برای تعداد بالای کاربران، معماری مش `WebRTC` سنگین می‌شود.
- در آینده می‌توانید `SFU` داخلی مثل `mediasoup` اضافه کنید.
